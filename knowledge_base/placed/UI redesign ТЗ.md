# ТЗ: редизайн UI Placed в минималистичном Material-подходе

## Цель

Переработать основной пользовательский интерфейс Placed, взяв за основу последний сгенерированный мокап:

- минималистичная светлая Material UI-эстетика;
- чистая левая панель параметров;
- крупная центральная зона превью;
- выбор исполнения по центру относительно зоны превью;
- компактные действия справа;
- нижний блок вариантов без миниатюр работы;
- параметры итогового оформления доступны через скрытую боковую панель.

Интерфейс должен выглядеть современно, спокойно и дорого, но оставаться рабочим инструментом, а не лендингом.

## Важные ограничения

1. Тёмной темы нет.
2. Labeler не менять без отдельного запроса.
3. Текущий backend API не менять в рамках первого этапа редизайна.
4. Renderer и алгоритмы подбора не менять в рамках первого этапа редизайна.
5. Новый UI должен сохранить текущую пользовательскую логику:
   - загрузка изображения;
   - история последних изображений;
   - выбор режима размера;
   - стандартные форматы;
   - ручной ввод размеров;
   - тип работы;
   - стиль интерьера;
   - применение оформления;
   - переключение "Универсальный" / "Авторский";
   - просмотр в интерьере;
   - скачивание превью;
   - ML-кандидаты цветов нижнего паспарту.

## Визуальная концепция

### Общий характер

Интерфейс должен быть похож на современное Material Design 3 приложение:

- светлый фон;
- мягкие карточки;
- скругления около 8 px;
- аккуратные тени;
- ровная сетка;
- понятные состояния кнопок;
- минимум декоративного шума.

Не использовать:

- тяжёлые градиенты;
- тёмную тему;
- стеклянный iOS/glassmorphism стиль;
- большие маркетинговые заголовки;
- лишние описательные тексты внутри интерфейса.

### Цветовая основа

Базовая палитра UI:

- фон приложения: тёплый белый / очень светлый серый;
- левая панель: белая или почти белая;
- границы: мягкий серо-бежевый;
- основной акцент: приглушённый зелёный / sage;
- текст: графитовый;
- вторичный текст: серо-зелёный / muted graphite;
- активные элементы: зелёная заливка с белым текстом;
- hover: лёгкое затемнение/подсветка без резких эффектов.

Палитра интерфейса не должна конкурировать с палитрой изображения и паспарту.

## Основная компоновка

### Desktop layout

Экран делится на две основные зоны:

1. Левая панель управления.
2. Центральная зона превью.

Правая панель параметров по умолчанию скрыта.

Рекомендуемые размеры:

- левая панель: 320-380 px;
- центральная зона: всё оставшееся пространство;
- минимальная ширина desktop: 1180 px;
- рабочая ширина: 1366-1920 px.

### Левая панель

Левая панель остаётся постоянной и содержит все входные параметры.

Порядок блоков:

1. Логотип / название:
   - `Placed MVP`
   - без большого подзаголовка.

2. Загрузка изображения:
   - крупная drop/upload зона;
   - иконка загрузки;
   - текст `Загрузить изображение`;
   - не перегружать техническим текстом.

3. Ранее загруженные:
   - горизонтальная лента миниатюр;
   - видимые элементы горизонтального пролистывания:
     - кнопка-стрелка влево;
     - кнопка-стрелка вправо;
     - можно добавить fade edges;
   - миниатюры квадратные или почти квадратные;
   - активная миниатюра выделяется зелёной рамкой;
   - удаление отдельных изображений можно оставить, но визуально не должно доминировать.

4. Размер работы:
   - segmented control:
     - `Автоматически`;
     - `Вручную`;
   - активное состояние зелёное;
   - неактивное состояние светлое.

5. Стандартный формат:
   - select;
   - показывать только в ручном режиме;
   - рядом можно оставить компактный tooltip, если нужен.

6. Физические размеры:
   - два поля в одну строку:
     - ширина;
     - высота;
   - между ними знак `×`;
   - единица измерения `мм`;
   - не использовать лишнюю линию, которая визуально перечёркивает заголовок.

7. Тип работы:
   - select.

8. Стиль интерьера:
   - select.

9. Применить:
   - крупная primary-кнопка на всю ширину;
   - состояние disabled, если параметры не изменились;
   - загрузочное состояние при расчёте.

### Центральная зона превью

Состоит из:

1. Верхней панели действий.
2. Большого превью.
3. Нижнего блока вариантов из палитры Placed.

## Верхняя панель превью

Важно: убрать дублирующие поля:

- не показывать `Размер`;
- не показывать `Исполнение`;
- не показывать `Интерьер`.

Эти параметры уже есть в левой панели и не должны повторяться в шапке превью.

### Центральный блок исполнения

Кнопки:

- `Универсальный`;
- `Авторский`.

Требования:

- блок должен быть визуально отцентрирован относительно именно зоны превью, а не всего окна браузера;
- кнопки находятся в одной строке;
- активная кнопка зелёная;
- неактивная светлая;
- ширина кнопок стабильная.

Под ними отдельной строкой:

- кнопка `Смотреть в интерьере`.

Требования:

- кнопка центрируется относительно `Универсальный / Авторский`;
- в обычном режиме показывает включение/выключение интерьерного превью;
- не должна спорить с primary-кнопкой `Применить`.

### Правый блок действий

Справа в верхней панели:

1. `Скачать`
2. `Параметры`

Требования:

- `Скачать превью` переименовать в `Скачать`;
- `Параметры` сделать читаемой горизонтальной кнопкой, не вертикальной вкладкой;
- у `Параметры` может быть иконка sliders/settings и chevron;
- кнопка открывает скрытую правую панель параметров.

## Центральное превью

Большая область с текущим оформлением.

Требования:

- превью должно быть главным визуальным объектом экрана;
- фон светлый, спокойный;
- если включён интерьер, показывать интерьерный фон;
- если интерьер выключен, показывать нейтральную зону просмотра;
- изображение не должно быть визуально зажато;
- не допускать растягивания или сплющивания работы;
- текущий zoom-on-hover сохранить, если он не мешает новой компоновке.

## Нижний блок вариантов

Заголовок:

`Другие варианты из палитры Placed`

Внутри два блока:

### Цвет паспарту

Показывать только 3 варианта.

Требования:

- это должны быть круги с цветами, без миниатюр картины;
- выбранный цвет выделяется кольцом;
- клик по кругу меняет цвет нижнего паспарту в ML-превью;
- порядок вариантов соответствует приоритетам ML-модели;
- если ML вернула больше трёх кандидатов, показывать первые три.

### Варианты рам

Показывать только 3 варианта.

Требования:

- не показывать миниатюры всей работы;
- показывать только L-образные уголки рам;
- уголок должен демонстрировать:
  - цвет;
  - текстуру;
  - примерный профиль;
- клик по уголку может пока быть неактивным, если бизнес-логика выбора рам ещё не готова;
- если будет активным, должен менять только визуальный вариант рамы в превью.

## Скрытая правая панель параметров

По умолчанию закрыта.

Открывается по кнопке `Параметры`.

Содержимое панели:

- параметры итогового оформления;
- размеры рамы;
- размеры верхнего паспарту;
- размеры нижнего паспарту;
- цвет верхнего паспарту;
- цвет нижнего паспарту;
- цвет/тип рамы;
- тип стекла;
- при необходимости техническая информация о ML-модели.

Требования:

- панель выезжает справа;
- ширина 320-380 px;
- при открытии не должна ломать масштаб превью;
- можно реализовать как overlay drawer поверх центральной зоны;
- закрывается по:
  - кнопке закрытия;
  - повторному нажатию `Параметры`;
  - Esc.

## Состояния

### До загрузки изображения

- зона превью показывает спокойный empty state;
- кнопка `Применить` неактивна;
- нижний блок вариантов скрыт или показывает skeleton.

### После загрузки, до применения

- изображение доступно;
- параметры можно менять;
- в зоне превью можно показать кликабельный призыв применить оформление.

### Во время расчёта

- показывать простой loader;
- не возвращать старую плашку со сменой статусов;
- результат появляется сразу после ответа backend.

### После расчёта

- показывать превью;
- показывать 3 цвета паспарту;
- показывать 3 варианта рам;
- `Параметры` становится доступна.

### Ошибка backend

- показать короткое сообщение об ошибке;
- не ломать текущий UI;
- пользователь должен иметь возможность повторить `Применить`.

## Адаптивность

### Desktop

Основной целевой сценарий.

### Tablet / узкий desktop

- левая панель может стать уже;
- нижний блок вариантов остаётся под превью;
- действия в шапке могут переноситься в две строки.

### Mobile

На первом этапе можно не делать полноценную mobile-версию, но интерфейс не должен разрушаться.

Минимально:

- левая панель сверху;
- превью ниже;
- кнопки в шапке переносятся;
- нижний блок вариантов остаётся доступным.

## Иконки

Не рисовать иконки вручную, если есть готовый вариант.

Рекомендуемый набор:

- Material Symbols / Material Icons;
- либо `@mui/icons-material`, если подключаем MUI;
- либо `lucide-react`, если останемся без MUI.

Для текущего направления подходят:

- upload;
- download;
- settings/sliders;
- chevron-left;
- chevron-right;
- image;
- home/interior;
- close.

## Material UI: подключать или нет

### Вариант A: без Material UI

Оставить текущий React + CSS и вручную реализовать Material-like стиль.

Плюсы:

- меньше зависимостей;
- проще сохранить текущую структуру;
- меньше риск сломать labeler;
- быстрее точечно внедрить редизайн.

Минусы:

- больше ручного CSS;
- сложнее поддерживать единообразие компонентов.

### Вариант B: подключить Material UI

Установить:

```bash
pnpm add @mui/material @emotion/react @emotion/styled @mui/icons-material
```

Плюсы:

- готовые компоненты: Button, Select, Drawer, Tooltip, ToggleButtonGroup;
- проще сделать Drawer параметров;
- проще поддерживать доступность и состояния.

Минусы:

- потребуется аккуратно переписать часть текущего UI;
- нужно настроить тему;
- есть риск визуальной "типовой MUI-админки", если не кастомизировать.

### Рекомендация

Для первого этапа редизайна лучше идти по варианту A:

- оставить текущий стек;
- вынести интерфейс на новые CSS-переменные и компоненты;
- реализовать drawer и новые блоки самостоятельно.

Material UI подключать только если после первого этапа станет ясно, что ручные компоненты начинают мешать скорости разработки.

## План реализации

### Этап 1. Структура UI

1. Не трогать `LabelerApp.tsx` и `labeler.css`.
2. Работать только с:
   - `frontend/src/App.tsx`;
   - `frontend/src/styles.css`;
   - при необходимости небольшими компонентами рядом с `App.tsx`.
3. Перестроить верхнюю панель превью:
   - убрать meta rows;
   - центрировать выбор исполнения;
   - перенести `Смотреть в интерьере` под выбор исполнения;
   - справа оставить `Скачать` и `Параметры`.
4. Добавить состояние `showParametersDrawer`.
5. Сделать кнопку `Параметры`.
6. Сделать drawer параметров.

### Этап 2. Левая панель

1. Привести upload-зону к крупному минималистичному виду.
2. Переработать `Ранее загруженные` в горизонтальный carousel:
   - стрелка влево;
   - список миниатюр;
   - стрелка вправо;
   - active state.
3. Проверить отступы между блоками.
4. Убедиться, что `Стандартный формат` показывается только в ручном режиме.

### Этап 3. Нижний блок вариантов

1. Заменить текущие карточки ML-кандидатов на 3 swatch-круга.
2. Использовать первые 3 ML-кандидата.
3. Добавить блок `Варианты рам` с тремя corner samples.
4. Для первого этапа frame samples могут быть визуальными, без смены алгоритма.

### Этап 4. Полировка превью

1. Проверить центрирование относительно preview area.
2. Проверить desktop 1366, 1440, 1920 px.
3. Проверить длинные названия файлов и select-значений.
4. Проверить disabled/loading/error состояния.
5. Проверить, что нет горизонтального overflow.

### Этап 5. Визуальная проверка

1. Запустить локальный frontend.
2. Проверить обычный режим.
3. Проверить интерьерный режим.
4. Проверить выбор `Универсальный` / `Авторский`.
5. Проверить загрузку разных изображений.
6. Проверить открытие/закрытие панели `Параметры`.
7. Сделать скриншоты desktop-состояний.

## Acceptance criteria

Редизайн считается готовым, если:

1. В шапке превью нет дублей `Размер`, `Исполнение`, `Интерьер`.
2. `Универсальный / Авторский` центрированы относительно зоны превью.
3. `Смотреть в интерьере` находится под ними.
4. Справа есть `Скачать` и `Параметры`.
5. `Параметры` открывает скрытую правую панель.
6. Внизу показаны ровно 3 цвета паспарту.
7. Внизу показаны ровно 3 уголка рам.
8. В нижнем блоке нет миниатюр картины.
9. У `Ранее загруженные` есть понятные элементы горизонтального пролистывания.
10. Интерфейс остаётся светлым.
11. Labeler не изменён.
12. Сборка frontend проходит.

## Будущая идея: AI-фоторендер

Отдельно зафиксировано на будущее:

можно добавить режим фотореалистичного превью через OpenAI image model, но не вместо текущего renderer.

Правильная архитектура:

1. Текущий renderer остаётся источником точной геометрии и цветов.
2. AI-слой используется только для фотореалистичности:
   - свет;
   - тени;
   - интерьерная атмосфера;
   - глубина;
   - фактура.
3. В UI это должен быть отдельный режим:
   - `Точный рендер`;
   - `Фотореалистичный рендер`.
4. Перед production-внедрением нужно проверить, насколько модель сохраняет:
   - исходное изображение;
   - цвет паспарту;
   - пропорции;
   - геометрию оформления.
